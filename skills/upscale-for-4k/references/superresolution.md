# 专用模型与批量处理

用于当前工具约束允许且已选用专用超分模型的任务。以下是处理与验证原则，不固定模型、设备路径、倍率或显存参数。

## 先找已有工具，再谈安装

- **声明“本机没有超分模型”之前必须实际查过**：只 `which` PATH 不够。依次查：项目内同类任务的清单与文档（如 `Document/ArtSource/*/manifest.json` 的 `model` / `settings` 字段、`.agents/rules/resolution/`）、用户级工具缓存（如 `~/.cache/*tools*`）、`find` 模型权重 / ncnn 可执行文件。已有同类批量记录时，沿用其模型、参数与流程。
- 在查完之前不向用户提议下载模型或改用纯重采样；用户已提示“本机有”时直接去查，不重复提问。
- 判据：先前同项目做过 4K 超分，则必然留有模型或其路径线索。落地：GSTetris 的 `~/.cache/gstetris-tools/realesrgan-20220424/realesrgan-ncnn-vulkan.exe`（含 `realesrgan-x4plus` / `-anime` 模型，`-n` 选模型、`-m` 指模型目录），此前 ClothGrid4K 用 `RealESRGAN_x4plus`。

## 小图标批量（Sprite 像素检测报告）

- 来源为 `GSSpritePixelCheck/Selected.md` 这类列表时，倍率取每行 `max(suggested宽/runtime宽, suggested高/runtime高)`，乘到**原图**像素并向上取整；不要直接用 suggested（它基于运行时裁剪后的尺寸，与原图宽高比可能略有差异）。
- “修复方式”列为“改导入设置”的行也先核对：若 suggested 仍大于原图像素，导入设置无法解决，需放大原图；只有原图已足够时才改导入。
- 倍率仅 1.0x–1.4x 时同样走模型流程，但柔边、发光、渐变类素材（如红点光晕）要对比模型输出与 Lanczos：模型可能锐化柔边，此时改用 Lanczos 并在交付中注明，不强行统一方法。
- 写回前并排预览（最近邻 / Lanczos / 模型）在深浅两种底色上检查；不改 `.meta`，保持 PPU。接入后核对消费者是否用 `SetNativeSize` 等依赖原图像素定尺寸，查不到就列为待验项。
- 提交时只 `git commit -- <路径>` 本任务文件，保护工作区其他在途修改；临时输入、输出和脚本放 scratchpad，收尾删除。

## 代表样本与批量边界

先挑能覆盖实际风险的样本：细线/文字、透明边、规则重复纹理及最大放大倍率。比较实际显示尺寸和局部放大，选择符合原画风格的模型；模型名称中的 general/anime 不足以证明它适合某类素材。已有用户认可的样本与批量授权时直接延续，无需每张图重复确认。

批量前记录源文件哈希、引用与目标规格；写回前复核源是否发生并行修改。先按消费者需要确定变体，再按源和转换参数复用计算结果，不能仅按源文件去重最终资源。

## RGB、透明度与倍率

- 对只处理 RGB 的模型，将 alpha 分开保存；透明区域的黑色隐藏 RGB 可能污染边缘，可在推理前用邻近可见颜色扩展。不要改变可见像素以制造扩边，最终 alpha 仍决定轮廓。
- alpha 可按目标尺寸独立重采样，以减少模型重画轮廓；它不是所有素材都适用的固定方案。像素画、细线及半透明发光需分别核对，尤其检查不透明内部、柔边和深浅底色上的晕边。
- 模型原生倍率高于目标时，先推理再缩小到精确目标。目标高于单次模型输出时，选择合适模型、多阶段推理或明确记录插值补足；不能把末端插值放大称为全程超分。多阶段会累积细节漂移，先在代表样本上判断是否值得。
- 大图分块推理保留上下文重叠并检查拼缝，块大小与精度按显存调整。不要把一次机器上成功的 tile、padding 或 float32 参数变成所有环境的硬限制。

## 验证与留存

区分两个比较基准：增强效果对比原图；裁切、重复压缩和拆块的几何重建对比相应处理前图。AI 输出不要求逐像素等于原图，但结构优化不能借 AI 差异掩盖可见内容丢失。

批量交付保留紧凑的溯源清单：可恢复的原图版本与哈希、实际模型及哈希、推理/重采样参数、目标路径/尺寸/哈希。涉及 Unity 时增加消费者、PPU、border、分块矩形或变体关系。按项目已有位置保存；模型权重、失败候选、一次性迁移脚本不进运行资源目录。可复用的脚本只有在实际需要维护时才纳入技能，不把单次迁移产物直接升级为通用工具。
