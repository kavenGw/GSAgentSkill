# 4K 图片升级

目标是让现有图片在目标显示尺寸下清晰，保留构图、身份特征和布局。像素尺寸合格与视觉质量合格分别验收。

## 确定实际需求

- 先定位资源、导入配置及消费位置，查找可用的高清原稿或矢量源；用户只贴检测日志时，先解释或诊断，不擅自替换资源。
- 区分原始文件像素、导入后运行时像素、实际屏幕占用。源图足够而运行时被降采样时，优先修正导入或图集设置。
- 4K 通常指 3840×2160 的屏幕，不意味着每张图都要导出为 3840×2160。UI 小图以实际最大屏幕占用为目标；背景根据铺满方式、宽高比和裁切范围计算。
- 等比升级倍率取 `max(屏幕宽/可用像素宽, 屏幕高/可用像素高)`，目标宽高向上取整。使用未舍入的测量值，必要时留少量余量；保持原始宽高比。
- Unity 项目接入前读 [Unity 资源接入](references/unity.md)，并遵守项目自身规则。
- 用户给出统一倍率时以该倍率为任务目标，不把某次项目使用的倍率推广成 4K 标准。若还要求消除节点缩放，分别计算显示尺寸保持与像素需求，不重复乘入已经计入屏幕测量的缩放。

## 选择方法

尊重用户已选的方法。没有明确方法时，依据素材和可用工具选择；只有无法判断保真要求或方法会明显改变画面时才提问。

| 素材条件 | 方法与边界 |
|---|---|
| 有高清、分层或矢量原稿 | 从原稿重导出，保留画布和锚点；优先于从小图推测细节。 |
| 简单几何 Logo、纯色图标、规则线条 | 可提议矢量重建；获用户同意后按可见轮廓重建并保留可编辑源，避免 AI 添加材质或改变品牌形状。 |
| 照片、插画、纹理且缺少原稿 | 使用可用的超分模型或图像编辑工具。增强细节可能包含推测，必须检查关键内容是否漂移。 |
| 用户要求仅重采样或像素画整数放大 | 用明确选定的插值方式；说明它扩大像素尺寸，不恢复原本不存在的细节。像素画通常保持整数倍和硬边。 |

工具选择服从当前工具和技能约束。AI 生图/编辑优先使用可用的 imagegen 技能及内置工具；纯重采样、程序化重绘仅在当前工具权限及用户授权允许时执行。说“工具不可用”之前先按 [superresolution.md](references/superresolution.md)「先找已有工具」查项目清单与用户级工具缓存，不能只看 PATH；确认没有再如实说明，不把插值结果冒充 AI 超分。不要为此静默安装大型模型或切换付费服务。

采用获准的专用超分模型处理透明素材或批量资源时，读取 [专用模型与批量处理](references/superresolution.md)。其中的模型流程不替代当前工具约束，也不要求每次任务安装本地模型。

## 保真执行

1. **先看真实图像**：读取尺寸、色彩模式、alpha 分布；透明图片在深浅底色上检查。透明像素中残留的 RGB 不属于可见轮廓，不能据此判断直角、圆角或边界。
2. **锁定不变量**：记录构图、画布比例、透明留白、颜色、关键线宽与文字/Logo 形状。用户要求裁透明边或拆块时，保持的是显示后的轮廓与位置，允许资源画布改变并补偿锚点和偏移。矢量重建以路径、圆弧、填充和裁切表达，不把原位图嵌进 SVG 当作重建完成。
3. **AI 约束**：附原图并明确其为编辑目标；要求保持上述不变量，仅提升清晰度。单独说明平面纯色或原有材质、透明背景要求。AI 重绘与专用超分不是同一方法，交付时说明实际使用哪种。
4. **控制重试**：先处理代表性素材并自行比对，再扩展同类资源。出现形状、文字或颜色漂移时做有针对性的修正；同一问题连续修正仍无改善就停止该路线，说明缺口并提出替代方案，不覆盖合格原图或无限重试。遵守用户已给出的预算与方法选择。
5. **精确导出**：实测生成结果的原生尺寸，不相信提示词指定值即为输出值。需要时做获准的裁切、画布调整或缩小；保留 alpha，避免透明边产生黑白晕边。若仍需插值放大，如实记录这一步。

不透明 4K 连续背景源图使用 JPG，默认质量 95、4:4:4（Pillow `subsampling=0`）；需要透明通道的资源保留 PNG。这不适用于所有 4K 素材，文字、Logo、像素画等按保真要求选择格式。仅转换格式时保持像素尺寸，更新源路径及哈希；源文件体积减少不代表运行包体或显存降低。

## 核验与落地

- 检查每张最终文件可解码、尺寸满足实际占用、宽高比与透明边距正确。原来有透明区域时，验证最终 alpha 及主体不透明度。
- 在实际显示尺寸和放大视图下分别对比；关注文字、眼睛、轮廓、细线、接缝、噪点和新增细节。需要像素比较时对齐画布，比较预乘 alpha 后的颜色和 alpha，忽略完全透明区域的隐藏 RGB。差异指标只作辅助，不能代替视觉检查。
- 替换前检查现有修改及其他引用。明确要求替换且引用范围允许时保留原资源标识；只改某一消费场景时避免影响共用图。维持布局、锚点、动画和加载行为。
- 保留最终方案仍用于编辑、重建的源文件及实际使用的提示词/转换参数，按项目已有位置存放；不把失败候选、临时脚本或备份资源留在运行目录。溯源清单记录的原图应实际可恢复，只有哈希不能替代未保存的原图。
- 交付说明文件位置、前后尺寸、实际方法、保真限制及已做的检查。只有在目标应用实际验证过，才称运行验收通过；静态像素达标不能证明运行图集已经更新。

## 任务产物清理

用户要求收尾或清理时，检查本任务的源文件目录（如 ArtSource），不只检查运行目录。按最终采用的转换链判断用途，不能因文件自称“可编辑母版”、未提交或未被运行时引用就认定该保留或删除。

- 确认不再用于编辑、重建或其他消费者的旧方案，将母版、残差数据、导出脚本和说明成套删除；旧脚本仍向现用资源路径写入过时尺寸、PPU 或渲染规格时尤其需要清理。能重现旧结果本身不是保留理由。
- 保留当前方案需要的来源、可编辑源和必要溯源信息，并说明具体用途。共享原图、归属不明或其他在途任务的文件不纳入本任务清理。
- 对比图与预览页按依赖成套处理；删除关联文件时同步清理本任务失效的链接和导出说明。实际检查删除结果，区分已删除与受阻项，不把计划删除报告成已完成。
